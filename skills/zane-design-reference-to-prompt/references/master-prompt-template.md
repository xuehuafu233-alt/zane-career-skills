# Master Prompt 模板

按任务裁剪，不机械填写空字段。

```markdown
你是一名资深产品设计师和前端工程师。请为【业务／受众】构建【页面／组件】，目标是【用户任务与转化目标】。参考材料只用于提取抽象的视觉语言、信息层级和交互机制；不要复制第三方品牌、专有文案、源码或受限资产。

## 成功标准
- 必须：...
- 应该：...
- 可选：...
- 禁止：...

## 内容与结构
1. 【区段】：目的、内容层级、主要元素、行动路径
2. ...

## 视觉方向
- 整体气质：用可观察特征解释，不只写形容词
- 排版：字体类别、层级比例、字重、行高、文本宽度
- 色彩：背景、正文、次级信息、强调和状态色的角色
- 布局：容器、栅格、对齐、间距尺度与密度
- 表面：圆角、边框、阴影、渐变、纹理和图片策略

## 组件与交互
- 【组件】：结构、默认状态、hover、focus-visible、active、disabled
- ...

## 动效
- 【触发】时，【元素】从【起始状态】到【结束状态】，约【时长范围】，使用【easing】。
- 运动必须支持中断，并为 prefers-reduced-motion 提供无位移或静态替代。

## 响应式
- 桌面：...
- 平板：...
- 手机：结构顺序、列数、导航、媒体裁切、触控与长文本处理...

## 技术与质量
- 技术栈：【已知栈；未知时保持实现中立】
- 语义、键盘操作、对比度、焦点、alt 和 ARIA：...
- 图片、字体、懒加载和动画性能：...
- 把【文案／图片／数据／链接】做成可替换配置，不硬编码第三方内容。

## 交付
- 输出【文件／组件／页面】。
- 保留或不改动【项目既有约束】。
- 完成后报告关键实现选择、假设和仍需用户提供的资产。

## 验收
- [ ] 页面层级与参考的抽象构图机制一致，但品牌与内容原创
- [ ] 桌面、平板、手机结构均符合上述规则
- [ ] 关键状态可见，键盘与 reduced motion 可用
- [ ] 无横向溢出、文字遮挡、图片变形或布局跳动
- [ ] 【业务特定的可观察验收项】
```

## 精度规则

- 有设计稿标注时可以写确定数值。
- 只有截图时优先写比例、范围和 token，例如 `紧凑 8 / 常规 16 / 区段 64`，并标记推断。
- 若品牌字体不可授权，描述字体属性并提供合法替代，不要求盗用字体文件。
- 若参考依赖视频、3D 或复杂滚动效果，同时给出低性能设备的降级方案。
