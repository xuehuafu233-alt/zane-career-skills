# 版本教训与 QA

## 反复出现的失败

- 资料库式结构信息很多，却没有招聘主线；
- 所有案例使用同一成功模板，职业责任和真实差异消失；
- 首页塞入口径辩护、SOP 和审计语言，失去选择功能；
- 图片只重复正文，组件只包装文字；
- 黑白结构未通过就加入颜色、卡片和动效；
- 用户指出一处就补一处，连续出现“修 A、坏 B”；
- 用户已经确认的规则没有自动写入合同，下一轮又从头讨论；
- 简历、网站、英文版和线上文本分别修，缺少共享事实与主张图；
- 把“至少两版”当作仪式，生成同骨架换色方案；
- 机器检查通过后没有实看完整页面；
- 候选目录通过就被误报为正式交付或线上部署。
- 用“候选／待部署”并列跳过用户确认闸门。
- 外部包只查`.DS_Store`等点文件，没有检查从隐藏真源继承的macOS hidden flag，导致终端有文件而Finder看起来为空。

## 发布检查

### 事实

- 职位、时间、本人／团队／协同边界一致；
- 数字有统计期、来源和证据等级；
- 已否决主张没有从旧版本恢复；
- 敏感数据和第三方信息已审查。

### 招聘

- 第一屏能复述定位、级别、独特价值和深读入口；
- 案例证明不同判断，不是同构成功故事；
- 网站、简历与深读页各自承担不同任务。

### 视觉

- 结构和视觉人格能追溯到当前用户；
- 桌面、窄宽和手机无溢出；
- 文档全部页面已渲染；
- 正文页无未解释的大块页尾空白；触发上方三分之二阈值时已有重新分页对照；
- 图片提供新增关系，数据权重匹配证据；
- 替换成另一候选人时不能无损套用。

### 发布

- 生成源、成品、资产与 manifest 一致；
- 图片、锚点、链接和权限正常；
- P0 为 0；
- 候选、待部署、已部署和现实反馈状态如实区分。
- 每个资产独立记录状态，不用网站已部署替代简历已确认；
- 平台改写HTML时使用语义一致性，不误把Pretty URLs当正文漂移，也不因此放弃版本检查。
