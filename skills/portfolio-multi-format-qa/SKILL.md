# Portfolio Multi-format QA

不能只读HTML源码或抽取Word/PDF文字后宣布通过。必须检查实际渲染结果，也不能只凭“链接看起来正确”宣布二维码和PDF链接可用。按[职业资产验收模型](../career-assets/references/evaluation-model.md)区分事实、招聘、语言、视觉、交互和发布证据。

若用户要从零建设作品集，先调用 `career-portfolio-builder`；本Skill只在已有可渲染成品后执行发布门槛，并把桌面、390px、全部文档页、链接和公开风险状态写回manifest。

## 1. 建立权威清单与数据账本

记录：网站主文件、同步副本、知识库/Word成品、生成源、信息图目录、线上地址。旧版本只用于比较，禁止覆盖当前权威版本。

同时建立关键主张账本，至少记录：

| 字段 | 例子 |
|---|---|
| 项目与指标 | 示例品牌A / 品牌联想份额 |
| 数值与单位 | 31.2%（虚构示例） |
| 统计日期或观察窗 | 20XX-06-30 / 前30天聚合 |
| 口径 | 累计、单月、峰值、支付GTV、是否含退款 |
| 证据类型 | 实际、测算、团队结果、同期变化 |
| 出现载体 | 简历、首页、深读页、图注 |

同一指标的日期、观察窗或证据类型不同，不得只统一数字。使用 [assets/claim-ledger.csv](assets/claim-ledger.csv) 对账。

## 2. 网站

- 桌面完整页面：首屏定位、层级、图片加载、链接、页尾。
- 390px手机完整页面：横向溢出、字号、按钮、长标题、卡片顺序。
- 验收必须覆盖首页和全部公开深读页，不得只检查首页；记录实际检查URL，避免把不存在的猜测路径列为404缺陷。
- 若用户指定Google Chrome，必须验证真实应用路径或进程，例如macOS的 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`；插件名称叫Chrome不等于实际连接的是Chrome。
- 当浏览器身份影响上传稳定性或用户明确指定应用时，同时记录应用路径、bundle ID／进程与实际可见窗口或可访问性树；工具返回的浏览器标签不能代替应用级证据。
- 桌面与手机均检查 `scrollWidth == clientWidth`。懒加载图片先滚动到页面底部，再检查 `complete && naturalWidth > 0`。
- 验证所有图片资源实际返回成功，不以本地显示代替线上检查。
- 对网站副本做内容或哈希一致性检查。
- 每次修改先检查当前元素、相邻关系与同类实例；事实、术语、共享组件、语言或断点问题必须枚举全部受影响页面。用户指出一处不等于 QA 范围只有一处。

## 3. Word/PDF

- 渲染全部页面为图片并逐页检查。
- 检查裁切、重叠、空白尾页、标题孤行、图注错位、中文字体、跨页衔接、两页密度和留白体感。
- 检查头像原始宽高比，禁止为填版面而拉伸。
- 二维码必须从最终PDF渲染页真实解码，不能只检查二维码源图；解码结果必须等于当前公开地址。
- 可见URL与PDF链接注释分开检查：文字印在页面上不代表可点击，链接注释存在也不代表目标地址正确。
- 修改生成源后必须重生，不手修成品造成源与结果漂移。

## 4. 跨载体对账

逐项比较简历、首页、深读页、图注与下载文档：

- 日期和观察窗：例如“截至7月”不能替代已经有证据的具体日期。
- 实际与测算：测算获客不能在另一处省略“测算”。
- 累计、单月与峰值：例如累计4,800条和当月2,900条不能混成同一口径（均为虚构示例）。
- 支付金额、GTV与退款：除非来源定义一致，不把它们自动视为同一指标。
- 本人动作、团队结果与同期变化：措辞强度随证据变化。

简历与网站不必逐字重复，但简历中的硬结果必须能在网站、公开证据或明确的面试口述边界中被承接。

## 5. 时间与因果

为“动作—中间信号—结果”分别标日期。若结果截图早于动作累计截止日期，不得暗示完整动作导致更早结果；可以改写为阶段观察、拆开两个时间节点，或只保留同期关系。

平台数据存在延迟时，写清“数据可核验节点”与“动作统计截止日”，不要用“最新”掩盖时序冲突。

## 6. 图文关系

逐图回答：它是否提供正文没有的关系、顺序、对比、边界或趋势？若只是把正文排版成图，删除或降级。

## 7. 信息图

- 普通流程箭头用次级色；关键决定/最终选择/结果用主色；停止/风险用警示色。
- 数据大小、颜色和位置必须匹配证据强度。
- 原始截图、人物照、Logo、项目封面保持原始证据属性，不统一滤镜。
- 多语言信息图必须检查图形内部边界，而不只检查网页是否横向溢出：逐项核对文字相对卡片、节点、箭头和画布的边界、箭头连续性、异常分隔符与层级遮挡。中文固定坐标替换为英文或其他语言后，重新核算文字容量。
- 采用双层渲染验收：先确认生成源与正式 SVG／图片同步并按原比例导出实看，再用真实目标浏览器打开网站实际引用的正式资源。静态生成器或图片库渲染通过，不代表浏览器字体宽度与页面组合一定通过。

## 8. 发布前检查

检查隐私与前雇主数据、联系方式、外链权限、旧数字回流、图片体积、生成源与成品、线上缓存和部署版本。大图若无证据保真要求，先压缩再发布。

外部Skill包或可分享文件夹还要检查Finder可见性：点文件扫描不等于hidden flag扫描。若源目录本身为隐藏工作区，复制后逐项检查并清除副本的macOS`UF_HIDDEN`标志、`.DS_Store`和`._*`，再从该副本生成ZIP；实际用Finder打开至少一个Skill目录，确认`SKILL.md`、`references/`、`scripts/`和`assets/`可见。

部署后从正式网站目录枚举真实 HTML 与关键静态资源路径，不猜 URL。对关键资源使用缓存破坏参数重新请求。不会被平台改写的SVG、图片、PDF等资源与本地正式文件做逐字节或哈希比对；若托管平台会对HTML执行Pretty URLs、压缩、注入或链接规范化，改用关键正文／结构命中、旧版本特征清除、真实交互与可逐字节资源比对，不把预期平台改写误报为内容漂移。HTML 返回 200、上传界面显示成功或浏览器能打开首页，都不足以证明当前部署正确。

部署动作还要核对：压缩包根目录没有多包一层；更新的是原目标站点；站名、域名和语言路径是否在授权范围；用户指定浏览器时用应用路径、bundle ID和可见窗口证明；记录新部署标识但不把它写进公开简历链接。

输出P0/P1/P2，并附：实际检查载体、检查日期、浏览器/渲染方式、二维码解码值、线上部署地址。没有P0时明确说明“可投递”，不为了延续优化而制造新一轮整体重构。
