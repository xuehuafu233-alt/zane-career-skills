# 职业资产验收模型

## 六层验收

| 层 | 核心问题 | 典型证据 |
|---|---|---|
| 事实 | 是否真实、可追溯、归因准确 | 主张台账、来源、时间和证据等级 |
| 招聘 | 是否增加相关、级别、价值或差异判断 | 陌生读者复述、删除测试、主张—证据映射 |
| 语言 | 第一读者是否自然理解 | 母语编辑、术语合同、AI味与翻译腔检查 |
| 视觉 | 层级、疏密、对齐和页面收束是否成立 | 全页渲染、同尺度基线对照、目标宽度截图 |
| 交互 | 链接、锚点、hover、focus、语言切换是否可用 | 从真实入口逐步点击与键盘检查 |
| 发布 | 线上是否来自权威源且可访问 | URL、部署标识、缓存破坏、资源或语义一致性 |

机器检查只能证明它实际检查的项目。页数、无溢出、HTTP 200 或上传成功不能替代招聘、语言与视觉通过。

## 通过标准

- P0：事实、归因、隐私、破图、不可达、二维码错误、明显裁切或发布错版本；存在即阻断。
- P1：明显影响招聘理解、深读选择、语言自然度、页面密度或移动端使用；本轮修复。
- P2：不影响理解、信任或行动的装饰偏好；记录但不阻断。

同类 P1 连续出现时，不再逐条修，按`change-control.md`升级为类别修复。

## 线上一致性

静态图片、SVG、PDF和不会被平台改写的关键资源可以做逐字节或哈希比对。HTML若被托管平台执行Pretty URLs、压缩、注入或链接规范化，不要求盲目逐字节一致；改用：

1. 权威源与发布包哈希；
2. 真实页面清单全部返回成功；
3. 关键新正文／结构命中；
4. 旧词或旧版本特征清除；
5. 真实目标浏览器渲染与交互通过；
6. 可逐字节资源继续单独比对。

不能因为平台会改写HTML，就放弃正文和版本一致性检查。
