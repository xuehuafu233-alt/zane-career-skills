# 决策记忆与变更控制

## 1. 自动维护决策账本

用户不需要反复要求“写进合同”。出现以下内容时，在当前任务范围内自动写入状态文件或决策合同：

- 确认：明确选择、认可或批准；
- 否决：明确不通过及原因；
- 事实纠正：职责、数字、时间、角色、术语或公开边界变化；
- 稳定偏好：对文风、疏密、视觉关系、工作方式的可复用判断；
- 停止线：哪些内容冻结、哪些不在本轮范围。

只记录会改变后续行为的决定，不把整段聊天复制进合同。用户的方案建议先标为`proposal`；确认后才变成`confirmed`。事实纠正不需要等到整阶段结束才记录。

## 2. 每次修改先做影响分析

把反馈先分类：

| 类型 | 处理 |
|---|---|
| 事实 | 立即改权威事实层，并枚举所有载体 |
| 体验 | 找出导致体验的结构、节奏、视觉或语言根因 |
| 方案 | 与目标和约束比较，不自动照抄 |
| 发布缺陷 | 检查源、构建、上传、平台后处理和缓存链路 |

然后检查四个范围：当前元素、相邻模块、同类实例、全部载体／语言／发布副本。修一处后至少复查前两层；事实、术语和组件级问题必须检查后两层。

## 3. 从补丁升级为类别修复

满足任一条件时，停止局部补丁：

- 同类问题第二次出现；
- 连续两轮出现“修 A、坏 B”；
- 用户重复提醒已经确认的决定；
- 需要为单个元素新增特殊字号、间距、颜色或定位规则；
- 候选、本地正式包与线上版本的状态开始混淆。

升级步骤：回到最近通过基线 → 找共享变量或真源 → 枚举全部实例 → 统一修复 → 全量回归。不得用新增说明文字、色块或动效遮盖结构问题。

## 4. 冻结与重开

已确认内容只因以下原因重开：新事实、证据冲突、目标岗位变化、目标市场变化、公开风险或客观 QA 缺陷。主观新鲜感和 Agent 想继续润色不是重开理由。

重开时只重开受影响层及其下游。例如术语事实变化会影响多语言文案和发布 QA，但不自动推翻已确认视觉人格；页面密度失败会重开排版和分页，不自动重写业务事实。

## 5. 每轮完成条件

每轮必须产生至少一种可验证增量：新事实进入台账、一个判断被确认／否决、一个载体完成、一个类别缺陷被消除、一个发布状态晋级或一个现实反馈回填。只重复讨论旧问题不算推进。
