# 职业资产阶段合同

| 状态 | 含义 | 谁可以作出 |
|---|---|---|
| `pending` | 尚未审核 | 初始值 |
| `approved` | 用户已明确确认当前对象 | 用户 |
| `waived` | 用户已明确放弃当前审核，允许继续生成候选版 | 用户 |
| `not_required` | 当前范围不涉及此阶段 | Agent 可提出，必须记录原因 |

`approved` 不代表后续所有阶段同时获批。`waived` 不等于质量通过，也不允许将候选版改称正式版。

| 闸门 | 必须向用户展示什么 | 通过后允许什么 |
|---|---|---|
| `task_contract` | 目标、输入、交付物、风险、完成证据 | 建立事实台账 |
| `evidence_position` | 事实／判断／假设分层、归因冲突、定位和待确认空缺 | 写完整黑白文本 |
| `content` | 全部黑白文本、删改理由和页数竞争 | 制作黑白结构 |
| `structure` | 一个结构假设及反事实检查；高不确定性时展示至少两种结构签名不同的黑白方向 | 进入视觉方向 |
| `visual` | 一个可追溯的视觉人格及反事实检查；高不确定性时展示至少两种关系机制不同的方向 | 生成可投递候选成品 |
| `qa` | 机器检查、全页实图、空白、断行、链接、二维码和跨载体对账结果 | 请求最终确认 |
| `final_confirmation` | 最终候选版与仍存风险 | 标记正式投递版 |

## 重开与一次性出稿

出现新事实、证据冲突、归因改变或用户要求重做时，将受影响闸门及其后续闸门恢复为 `pending`。

用户可以明确要求跳过中间选择。此时逐项记录 `waived`，而非填写虚假的 `approved`。Agent 仍要执行事实、安全和 QA 检查，并将成品标为候选版。

异步或一次性出稿时，向用户展示一个可整体确认的 waiver 请求对象：`将跳过哪些选择 / Agent将自主决定什么 / 仍强制执行什么 / 产物只能称为什么 / 哪些动作仍未授权`。只有用户明确接受，才逐项记录`waived`；“请一次性做完”本身不自动等于放弃全部审核。

## 决策账本

闸门记录阶段授权，决策账本记录后续不能遗忘的内容。用户确认、否决、事实纠正、稳定偏好和停止线出现时自动登记；不要等用户再次要求“写进合同”。

资产闸门与现实链路状态分开：候选／确认／交付只说明材料状态，不能替代已投递、已面试或已获得招聘反馈。

每项决定至少包含：`area / status / statement / reason / affects / time`。用户提出的方案未确认前记为`proposal`；Agent 基于证据给出的当前建议记为`recommended`；明确选择后记为`confirmed`；明确不用记为`rejected`；长期边界记为`constraint`。

一个决定若影响事实、术语、组件或发布链路，必须枚举全部受影响载体；不能只修改用户指出的一个页面。
