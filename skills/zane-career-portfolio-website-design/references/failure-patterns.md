# 失败模式与裁决问题

## 1. 首页变成审计报告

信号：口径、限制、证据类型和过程说明都堆在入口页。

裁决：这句话是否改变招聘者点击哪个案例？若否，下沉深页、证据库或面试材料。首页保留责任、决定、结果和深读理由。

## 2. 用组件替代判断

信号：地图、时间线、标签、卡片、表格都好看，但页面仍死板。

裁决：组件是否表达了正文没有的顺序、对比、范围或关系？若没有，删除。四段经历不因数量为四就必须排成四个同构节点。

## 3. 每个案例同样重

信号：相同尺寸、颜色、数字权重和说明长度让职业路径消失。

裁决：先按倒序、责任与证据强度定主次，再分配面积、对比和饱和度。允许主案例、验证带和轻入口使用不同结构。

## 4. 把“不好看”当作缺动效

信号：静态层级未成立就增加滚动揭示、视差或入场动画。

裁决：关闭 JavaScript 后，阅读路径是否成立？若不成立，回结构或对比。动效只能强化已经成立的关系。

## 5. 参考网站变成拼贴

信号：从多个组件库搬来人物、地图、数字和悬浮效果，单看都精致，合起来没有同一语法。

裁决：先提取参考中的关系机制，例如“右图保持完整”“悬浮揭示范围”，再用本站的字体、色彩、间距和证据重新表达；不复制表面构件。

## 6. 用户反馈驱动方向漂移

信号：用户说往东就改东，下一轮又回西；设计者失去主导。

裁决：把反馈标记为事实、体验或方案。事实纠错；体验寻找根因；方案与整体目标冲突时明确否决。疲劳状态下不要求用户继续充当美术指导。

## 7. 局部修补形成补丁堆

信号：为修留白加说明，为修说明加色块，为修色块加动效。

裁决：连续两轮互相破坏即回到最近通过版本开新分支。一次只改变结构、静态视觉、交互或动效中的一层。

## 8. 链接存在但不算直达

信号：案例先到导览页，或锚点因懒加载图片布局变化被推走。

裁决：从首页真实点击，在资源加载完成后检查目标标题仍在视口。代码中存在 `#id` 不等于用户无需再次寻找。

## 9. 无限追求“惊艳”

信号：信息、信任和操作都已成立，仍因为装饰偏好不断重构。

裁决：比较新改动能否提高理解、信任或点击。若只能改变主观新鲜感，列为 P2 并冻结。

## 10. 用像素尺寸冒充清晰度

信号：把低清 JPEG 放大到 2K／4K 后，宣称细节已经恢复。

裁决：区分真实源文件、确定性重采样和生成式重画。先检查模糊来自源压缩、容器放大还是 `cover` 裁切；只有更高质量真源能增加真实细节。

## 11. 用同主题素材替代项目证据

信号：另一场活动或另一支作品更好看，且品牌、主题或口号相似，于是拿来做当前案例封面。

裁决：招聘者会否合理误以为该素材属于本人参与项目？若会，否决。主题一致不能替代项目归属，删除署名也不能改变来源。

## 12. 去字成功但画面修坏

信号：字幕或水印消失了，但星空、衣服、人物或复杂背景留下暗斑、涂抹和重复纹理。

裁决：把背景自然度与文字去除同时作为通过条件。修复痕迹可见即回退；优先选择无需修复的相邻帧或原始资产，不为完成指令牺牲可信度。

## 13. 候选通过被说成已经交付

信号：候选目录渲染通过，就宣称待部署包或线上版本已更新。

裁决：逐级记录候选、交付包、线上三个状态。晋级前查文件／哈希／链接差异；晋级后从正式包重跑验收和校验；实际部署后再验证公开 URL。

## 14. 页尾动效外溢成全页表演

信号：联系方式的深色终章有效，于是给每个经历和作品都加入滚动揭示。

裁决：终章切换只表达一次“阅读 → 联系”。其他区域仍需在静态状态下成立；不吸附、不锁滚动，移动端与减少动效直接显示终态。

## 15. 全部深页强制同构

信号：案例长文、关于我和作品画廊都被套进相同侧栏、摘要卡和章节模板。

裁决：先问每页要帮助招聘者完成什么任务。统一字体、色彩、间距和交互语法，不统一页面骨架；案例读证据，关于我读人，画廊看作品层级。

## 16. 新 CSS 写了黑白，真实页面仍有颜色

信号：覆盖规则插在旧样式中段，后续权威层重新带回蓝色，却因只读源码或局部截图被宣布通过。

裁决：读取真实计算样式并渲染全部页面。界面黑白不等于证据灰度化；Logo、截图与原始证据保持原色。

## 17. 证据图比正文宽，但没有形成节奏

信号：图片只在正文两侧各跨出一小截，既不像通栏证据，也不像正文插图，页边距不断跳变。

裁决：为普通证据图设稳定宽度，并明确它与正文的对齐关系。允许“证据比叙述宽”，但宽差必须足以被读成层级，而不是排版误差。

## 18. 换了职业和颜色，网站骨架没换

信号：工程师、销售、运营等候选站都使用大字 hero、横向数字带、左标题右正文、主案例卡和深色联系区；每份合同却用一个完全不同职业作反例并宣布不模板化。

裁决：记录六项结构签名，用相近岗位或相近证据形态做最近邻替换。四项及以上可无损复用时回到黑白结构；至少比较一个取消指标带、取消 hero 或改变主阅读轴的方向。颜色和行业词不计结构差异。

## 19. 正文被“优化”为另一篇文章

信号：用户给了 Word／Markdown 正文并要求按文档编排，页面却出现 Agent 新增的总结、改写、抽象标签或更均匀的段落节奏。

裁决：先做段落、标题、列表和图注基线。没有明确改写授权时，正文逐字保留；设计只改变承载关系。任何差异必须能回指用户授权或事实纠正。

## 20. 把段落复述画成图

信号：图把正文中的句子换成卡片、节点、流程或口号，却没有新增方法来源、数据、对比、关系或可验证证据。

裁决：图片必须证明正文之外的独立事实或方法，且能说明来源与边界。否则撤回图，不用图注或“过程证据”说明替它赋予证据价值。

## 21. 双语“加载成功”冒充对应完成

信号：英文图片能加载、没有越界，或 OCR 没有中文，就宣布中英文已对齐；但章节、图序、关系、段落范围或职责边界已经漂移。

裁决：建立逐页对应矩阵，比较标题、摘要、段落／列表、事实、图序、关系和图注。原始中文界面可保留，但要说明它是原始证据，不把 OCR 结果当翻译验收。

## 22. 局部 QA 冒充全站 QA

信号：只检查用户指出的页面、单张截图、静态资源或 `img.complete`，却在回复中写“全站通过”；或者审计脚本自身的相对 URL、视口时序制造假失败／假通过。

裁决：从首页真实入口覆盖全部页面和目标视口；先设视口再导航；资源加载后复查锚点；相对链接按当前文档 URL 解析；人工视觉、运行时脚本和交付状态分别留证，任一缺失只能写局部通过。

## 23. 生成源、交付包、线上版本混为一谈

信号：生成器跑完、候选截图通过或本地服务器可打开，就把作品集称为“最终／已部署”；旧线上仍有不同口径却没有在状态中分开。

裁决：分别记录源文件、正式交付包、公开 URL 与现实反馈。晋级后从正式包重验，线上必须从公开 URL 重验；没有用户确认、部署实测或现实反馈，不跨状态宣称。
